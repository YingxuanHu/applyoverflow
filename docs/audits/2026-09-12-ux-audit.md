# ApplyOverflow UX Audit and Fixes

Date: September 12, 2026. Baseline: `a86cf58` plus the existing uncommitted platform changes and this UX patch.

## Scope and Release Status

This is a hands-on local audit, not a claim that every possible workflow or production configuration has been verified. Chromium was driven primarily through Playwright CLI against the actual application and local PostgreSQL fixtures. Final checks used the Next.js standalone production build at `http://127.0.0.1:3000`, with ingestion disabled. No production data, services, or deployment were changed.

The unauthenticated request to `https://applyoverflow.com/jobs` timed out during connection establishment after 5 seconds around 09:00 UTC. A control request to GitHub returned HTTP 200 in 0.31 seconds. This establishes a reachability problem from this machine, not a confirmed global outage or its cause. Authenticated production UX remains unverified.

**Do not treat this report as release approval for the entire dirty worktree.** Three earlier platform changes still need the corrections described under Release Blockers.

## Implemented Fixes

| Problem reproduced or inspected | Change |
| --- | --- |
| Auth forms mounted twice for responsive layouts, producing duplicate IDs/ambiguous labels and separate form state | Render children once in `src/components/auth/auth-shell.tsx`. Preserve one form across viewport changes and retain safe-area spacing. |
| Unverified-email errors were shown as invalid passwords because the message substring check missed "verified" | Match the provider error code using `src/lib/auth-sign-in-error.ts`; provide the verification recovery path. |
| Authentication outages and network failures blamed the password or left recovery unclear | Distinguish unavailable, network, rate-limit, and credential errors; reset pending state and retain entered values. |
| Missing/duplicate landmarks and unnamed controls | Give auth forms an accessible level-one heading, remove the nested resume loading `main`, name the account menu and application-status/currency selects, and keep mobile filter labels accessible. |
| Low-contrast secondary text and dark primary controls | Correct text colors on Jobs, Picks, Documents, Settings, and sidebar navigation. Separate bright dark-theme text accents from darker fills behind white control text. |
| Theme options looked like radio buttons but lacked native arrow-key behavior | Replace custom button roles with native grouped radio inputs, visible keyboard focus, and the same segmented appearance. Remove the moving selected background that briefly separated text from its contrasting fill. |
| Password managers lacked account context in Settings | Add username autocomplete metadata to password forms and current-password autocomplete to account deletion. |
| Resume library entries could be created but not removed from active selections | Add an owner-scoped archive action and confirmation dialog. Archive only the entry; retain versions, profile content, and saved build snapshots. |
| Detail-panel salary ranges were truncated | Wrap critical detail values rather than ellipsizing them. Keep the master/detail panel heights equal. |
| Single-result heading said "1 matching jobs" | Use singular/plural job wording correctly. |
| AI search and microphone errors were not announced as alerts | Add alert semantics to inline error feedback. |
| Global smooth scrolling interfered with Next.js route scroll handling | Add the documented `data-scroll-behavior="smooth"` root marker. |
| Playwright screenshots/snapshots triggered repeated development rebuilds | Exclude audit output from the development watcher and Git. Keep artifacts under `output/playwright/`. |
| The existing browser regression used an API cookie path that did not represent local production-mode browser authentication | Use UI sign-in and same-origin browser requests, revoke the test session, create the screenshot directory, and assert save/remove cache consistency, mobile focus, panel equality, and unclipped detail values. |

Changes already present before this UX pass, such as lossless descriptions, lazy detail loading, mobile detail navigation, and viewer-state cache overlays, were exercised by the regression tests. They are not newly attributed to this pass.

## Release Blockers in Earlier Changes

These are code-level risks in the surrounding uncommitted platform work, not regressions introduced by the UX fixes above. They remain unresolved.

1. **P1: Storage retry can delete a still-referenced document.** `runDurableStorageDeletion` in `src/lib/storage/index.ts` persists a retry task and throws on failure. Callers such as `deleteProfileCoverLetter` in `src/app/profile/actions.ts` then retain the document record. A later retry can delete its file while the record still appears valid. Make record deletion and durable intent transactional, with file removal occurring only after commit; separately handle cleanup of uploads that never acquired a record. Add a caller-level storage-failure/retry test. The current helper-only test does not cover this invariant.
2. **P2: Publication scope rejects legitimate GENERAL jobs.** `isExcludedJobTitle` in `src/lib/jobs/scope-policy.ts` still rejects titles such as Pharmacy Benefits Analyst, Dental Billing Specialist, and Police Records Clerk. Narrow occupation exclusions without admitting patient-facing/manual roles. Test intake and publication paths, not just the regex. The root `AGENTS.md` explicitly includes non-clinical healthcare administration and public-sector knowledge work.
3. **P2: App-only releases can use old migrations.** `deploy/single-vps/rebuild.sh` builds `$BUILD_SERVICES` but runs migrations from `worker-maintenance`. When only the app is rebuilt, that image can contain an older migration set. Always build/use a migration runner from the exact release revision, without unnecessarily restarting workers; test the app-only deployment path.

The production connectivity uncertainty must also be resolved independently before release. None of these items was tested by destructive production actions.
